# Muse: входящие команды и постоянная подписка LOST

## Исправление 2026-10-26

На Mac mini AK сообщения LOST доходили до Muse, но вызовы device.health из диалога завершались тайм-аутом. Успешная регистрация и доступность чата не подтверждали работу входящих команд.

Контрольный запуск стандартного Service/LinkSession без предварительной подписки дал настоящий link.invoke → executor → link.result. При постоянной подписке на общем соединении входящих команд не наблюдалось. Переключение только основного/отдельного чата и удаление явного device_id не дали подтверждённого исправления. Heartbeat также не устранил тайм-аут; эксперимент удалён. Внутренняя причина такого поведения на стороне Muse не установлена.

В chat_adapter.py разделены управляющее и чат-соединения внутри одного процесса. Управляющее соединение выполняет единственную link.register и обслуживает команды. Отдельное незарегистрированное Noise-соединение выполняет текстовые/голосовые HTTP-запросы и подписку исходного LOST side-chat. Это сохраняет прежнюю идентичность, приватный диалог и SDK.

При обрыве HTTP чат-канал переподключается; при отказе авторизации закрывается control, чтобы штатный Service обновил bearer. Остановка модуля завершает обе задачи/соединения. Изменения SDK/vendor, nonce, маркеры и main-chat эксперименты не входят в итог.

- [Официальный control/result](https://github.com/facebookincubator/muse-gadget-sdk/blob/c9354b7a765cfb7dd3c4f1945a9ca838d871630c/esp32/main/noise_control.cpp): формат link.invoke/link.result совпадает с Python; менять его не требовалось.

## Доказательства и границы проверки

17:50:40 МСК: на mini при раздельных каналах получен реальный device.health, выполнен с ok, отправлен link.result с соответствующим ID. В исходном LOST side-chat получено сообщение SUCCESS. Независимая проверка получения каждого поля payload одноразовым nonce не выполнялась; её подготовка удалена, дополнительные сообщения по просьбе пользователя прекращены.

На Intel Monterey/Python3.9 прошли все14 актуальных canonical-тестов адаптера,4 новых транспортных теста и7 Node-тестов gateway/supervisor. Новый стенд использует реальное Noise-рукопожатие и шифрованный framing поверх очередей без сети/credentials. Проверяются единственная регистрация, доставка invoke/result при открытой подписке, текст/голос через чат-соединение, subscribe404 перед первым POST, закрытие обеих сессий, восстановление HTTP и отказ авторизации.

При финальной проверке сохранён один Muse runtime, две Noise-сессии, одна регистрация. Core не перезапускался, Live продолжал отсчёт, UPS/VPN/Flame/Muse были ready. Новых зависимостей, нативных сборок или изменений разрешений macOS нет.
