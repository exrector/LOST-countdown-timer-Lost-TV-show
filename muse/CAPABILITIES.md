# Muse / Tomagochi в LOST: функции и реализация

Дата проверки: 25 октября 2026. Подключение к Muse и функциональность интерфейса — разные результаты. До голосового теста нельзя считать русский голосовой диалог подтверждённым.

## Что уже проверено

- Новая пара с Raspberry Pi сохранена; Pi выключен. Credentials перенесены на Mac без повторного BLE-сопряжения.
- На рабочем Mac проверена реальная регистрация с Muse через Noise. Старый SDK заменён на закреплённый актуальный Linux SDK `c9354b7a765cfb7dd3c4f1945a9ca838d871630c`.
- На Intel Monterey 12.7.6 установлен и запущен модуль под Python 3.9.6 с бинарными зависимостями. На mini подтверждены Noise и registered with the Muse; оба окна LOST, UPS и таймер работают. Системный Python и macOS не обновлялись.
- Переключатели UPS/mUse и состояние модулей отделены от независимого таймера. Закрытие интерфейса ассистента не означает отключение всего модуля.
- Сеть первого запуска: включённый владельцем VPN роутера. Изолированный американский SSH/SOCKS-маршрут ещё не реализован и не доказан.
- На Mac mini сейчас обнаружены только аудиовыходы: встроенный динамик, DisplayPort и HDMI. Аудиовхода для записи нет. Нужен подключённый микрофон; выбирать конкретную модель для этого не требуется.

## Карта возможностей

| Функция | Что есть в SDK | Как использовать в LOST | Готовность |
|---|---|---|---|
| Постоянное соединение, авторизация, переподключение | Noise/WSS, обновление токенов, backoff | Один фоновый модуль под управлением LOST | Подключение проверено на рабочем Mac и на Intel Monterey mini (Noise + зарегистрированная сессия) |
| Текстовый запрос | `send_chat()` | Поле ввода в режиме AI; русский текст можно показывать независимо от клавиатурной раскладки | Транспорт есть; интерфейс не подключён |
| Поток ответа | `subscribe_chat()`, NDJSON | Печатать текст по мере прихода, затем сохранять завершённый ответ | API есть; адаптер/UI нужны |
| Голосовой запрос | `send_voice(wav_bytes)`, WAV до 2 MiB | Нативная запись микрофона → WAV → отправка через текущую Muse-сессию | API есть; запись и русский язык не проверены |
| Ответ голосом | `output_modality='voice'` и `stream_tts(message_id)` → MP3 | Дополнительная настройка «озвучивать ответы»; воспроизведение средствами macOS | Есть в коде Python SDK; доступность и русский голос в реальном аккаунте не подтверждены |
| Обычный ответ текстом | `output_modality='text'` | Основной режим терминала | Выбранное направление UI; показ ответа ещё нужно реализовать |
| Удержание клавиши для речи | Не зависит от SDK: локальные keydown/keyup | Нажал PF4 → запись; отпустил → отправка | Предпочтение владельца, реализация впереди |
| Нажатие-переключатель записи | Локальная логика | Не включать по умолчанию: владелец выбрал удержание | Не требуется первым этапом |
| Завершение по тишине / непрерывный разговор | Нужны собственные VAD, циклы записи, прерывания, управление эхом | Возможный последующий режим, если ручная запись уже работает | Не считать готовой функцией Python API |
| Состояния персонажа | В ESP32 есть BOOT/IDLE/LISTENING/THINKING/SPEAKING/ERROR/OFF | Собственная монохромная анимация внутри терминала | Нужен renderer LOST |
| Уровень голоса / движение рта | В ESP32 есть локальный `level` 0..1 | Индикатор при записи; рот по амплитуде при реальном воспроизведении | Реализуется локально; фонем/viseme в проверенном API не найдено |
| Пиксельный аватар | Процедурный renderer ESP32 64×64 | Собственный спрайт/Canvas в цветах терминала, масштабирование без сглаживания | Это пример реализации, не автоматически присланный аватар Mac |
| Реакция на взаимодействие | Локальная реакция `happy`/«поглаживание» в ESP32 | Клавиша или действие «позвать»/погладить | По желанию; не облачная шкала эмоций |
| Подпись / картинка | Примеры `display.set_caption`, `display.draw_url`; ESP32 также `display.draw_file` | Зарегистрировать собственные обработчики, показывать картинку или подпись в области AI | Требует обработки и отображения на Mac |
| Дополнительные кнопки / действия | `commands_v2` в `link.register` | Ограниченный набор действий LOST, журнал, будущие модули | SDK позволяет расширение; каждую функцию нужно реализовать и объявить |
| Работа с компьютером | `system.run`, `file.read`, `file.write`, `device.health` | Сохранённые возможности gadget runtime от имени пользователя macOS | Это реальные команды SDK; интерфейс питомца от них не зависит |
| Контекст чата | `session_id` | Одна сохраняемая сессия терминала, без создания нового разговора каждым нажатием | Возможность протокола; политика контекста ещё нужна |
| Журнал разговора | События чата дают материал для истории | Локальная ограниченная история, прокрутка, очистка из меню | Это наша функция; не журнал таймера |
| Голод, усталость, возраст, развитие питомца | Готовой модели Tamagotchi в проверенном SDK нет | Отдельная игровая логика, если захотим | Не добавлять как обязательную часть первого релиза |
| Видео | Отдельный протокол тестового приложения телефона → ESP32, H.264/VP8 | Для голосового терминала не нужно | Не путать с видеопотоком персонажа Muse |
| Сенсоры, реле, свет, GPIO, ESP32 power/OTA | Платы и их обработчики | На Mac нужны отдельные устройства и модули | К нашему Mac автоматически не относятся |

Термин «Tamagotchi» здесь — концепция интерфейса. SDK не заставляет делать отдельное окно и не поставляет универсальный набор эмоций/анимаций для macOS.

## Голосовой сценарий — выбран удерживаемый PTT

1. `AI` + Enter или PF3 открывает ассистента внутри терминала. Таймер продолжает работать независимо.
2. Удерживаем PF4: начинается запись, видны «СЛУШАЮ», длительность и уровень микрофона.
3. Отпускаем PF4: запись закрывается и отправляется через существующую сессию Muse. Повтор клавиши игнорируется.
4. Терминал показывает «ОТПРАВЛЯЮ», затем «ОЖИДАЮ ОТВЕТ» и поступающий текст.
5. Escape во время записи отменяет запись. Потеря фокуса, блокировка клавиатуры или отключение микрофона также отменяет её: запись не должна зависнуть после пропущенного keyup.
6. Во время ожидания повторная отправка блокируется до определённого поведения отмены/очереди. При сетевой ошибке не отправлять автоматически несколько копий одного вопроса.
7. Первый вариант: mono PCM 16 kHz/16-bit WAV, запись не больше 45 секунд, что укладывается в лимит 2 MiB. Это проектный формат, а не уже проверенный на сервере контракт распознавания.
8. Микрофон включается только при осознанном удержании. Автоматической фоновой записи и wake word в первом варианте нет.
9. Звук и голос ассистента не меняют расписание, громкость или длительность штатных предупреждений LOST. Приоритет предупреждений таймера и политика микширования задаются отдельно; на время сирены запись не должна превращаться в голосовой запрос самой станции.

Русскую речь нужно проверить реальным запросом с микрофона. До этого поддержка русского не считается доказанной ни по наличию WAV API, ни по удачной регистрации устройства.

## Клавиатура Informer 213

Сверены фото IMG_3116 2.HEIC и текущая прошивка v3.1; сами клавиши заново физически не нажимались.

- RESET отправляет Left Ctrl: не переназначать.
- IDENT отправляет Escape; FIELD MARK — внутренний Fn прошивки.
- PA3 ATTN = Home, CURSR SEL = End, DUP = PageUp, ERASE EOF = PageDown, CURSR BLINK = CapsLock. Сохраняем стандартные назначения.
- PF1/PF2 управляют яркостью, PF7–PF12 — медиаклавиши/громкость: сохраняем.
- PF6 сворачивает LOST для доступа к рабочему столу: сохраняем.
- PF3/PF4/PF5 сейчас отправляют F3/F4/F5 и не привязаны к действиям LOST. Предложение: PF3 открыть AI, PF4 удерживаемая запись; PF5 пока резерв.
- В пользовательских системных сочетаниях mini найдены модифицированные F3/F4/F5, простые F3/F4 не обнаружены. Окончательный тест — реальные нажатия на устройстве.
- Верхние подписи PF13–PF24 — второй слой тех же физических клавиш. В текущей прошивке нет их отправки: слой потребует отдельного изменения/проверки firmware. Для PF3/PF4 он не нужен.
- Буквы S/D/L/Q/U больше не должны запускать звук, режимы, выход и UPS из обычного экрана. Пауза и вход в меню сохраняются. Остальные действия доступны через меню.
- В обычном LOST ввод кода активируется только штатным таймером. Команда AI должна распознаваться отдельно от поля цифрового кода и не включать преждевременно произвольный ввод. В финальные четыре минуты/во время ввода кода приоритет имеет код станции; правила выхода из AI задаём явно и проверяем.
- Локальный AI-интерфейс реализован: PF3 и AI + Enter открывают его, Escape/PF3 закрывают; при окне кода LOST AI блокируется. PF4 отправляет запрос PTT только при доступном и подключённом нативном адаптере; запись звука пока не реализована.

## Визуальное решение

Первый интерфейс — отдельный режим существующего терминала LOST: текст разговора, короткий статус и индикатор записи. Он использует имеющийся WKWebView и может содержать Canvas/спрайты; это не ограниченный ANSI-терминал. Отдельное окно для такой функции не требуется.

Персонажа можно добавить в том же режиме позже: ожидание, слушает, занят, ошибка, печатает ответ. Эти состояния привязываются к фактическим событиям, а не к случайной смене эмоций. Озвученный персонаж, рот по аудио и собственный характер не блокируют первоначальный голосовой ввод с текстовым ответом.

## Порядок реализации

1. Фоновый модуль: перенос пары, запуск на Monterey, включение/отключение в меню, восстановление процесса без воздействия на часы LOST.
2. Текстовый режим AI и подписка на поток ответа; явно отделить его от ввода числового кода станции.
3. Подключить микрофон; нативный захват на Monterey, разрешение macOS, удерживаемый PF4, отправка WAV и проверка русского языка. Это приоритетный функциональный этап, не необязательное украшение.
4. Приёмочные сценарии: press/hold/release, repeat, blur, keyboard lock, USB mic unplug, timeout, offline/reconnect, приближение срока ввода кода и работа предупреждений LOST.
5. Состояния/пиксельный персонаж внутри терминала.
6. Отдельно проверить голосовые ответы; добавить только после реальной проверки серверной TTS, языка и воспроизведения. Текстовый ответ остаётся полноценным режимом.
7. Игровое поведение, постоянный hands-free, изображения и отдельное окно — по необходимости после рабочего диалога.

## Локальный интерфейс — результат 25 октября 2026

Режим AI проверен в нативном WKWebView и браузере: открытие PF3/AI+Enter, ввод сообщения, поступающий тестовый ответ, возврат и блокировка AI при четырёхминутном окне кода. Снимок LOST-AI-preview.png показывает явно обозначенный тестовый режим без обращений к Muse. Подготовлен локальный защищённый API и side-chat адаптер с offline-тестами; сквозная проверка нового экрана с реальным Muse и голоса не проводилась. Mini разобран владельцем для установки микрофона, после этого удалённые проверки и установка нового UI остановлены.
