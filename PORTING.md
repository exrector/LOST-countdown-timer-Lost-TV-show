# LOST — переезд на другой компьютер (Mac mini и т.п.)

Дата заметки: 2026-09-30. Статус: **готово на MacBook Pro (M2 Max), на целевом компьютере ещё не проверялось.**
Задание для переезда даст владелец, когда соберёт компьютер. Эта памятка — чек-лист, чтобы ничего не выяснять заново.

## Что уже готово
- Программа целиком в папке `LOST`. Запуск: **`LOST.app`** (или `cast-app/start.command`). Одна программа: сервер + таймер на втором экране + терминал на главном.
- Архив для переноса: `./make-archive.sh` → `LOST-portable.zip` (~7 МБ). Внутри всё нужное: страницы, звуки, `cast-app`, помощник звука `bin/lost-audio` (универсальный Intel+Apple Silicon), `LOST.app`.
- Оригинальные `index.html`, `console.html`, `js/lost-timer.js` не изменены; вся надстройка в `cast-app/` (`bridge.js`, `server.js`, `start.js`, `config.json`).
- Беспроводное (Chromecast, Raspberry Pi) **отменено**, код лежит как архив (`output: chromecast|both|external`, папка `cast-app/pi/`) и в работе не участвует.

## Чек-лист на новом компьютере
1. **Система и процессор.** Mac mini 2014 = Intel, macOS максимум 12 (Monterey). Узнать: «Об этом Mac».
2. **Node.js — ставить вручную (в архив не входит).** Для Monterey нужен **Node 20 LTS (x64)**; Node 22 требует macOS 13.5+ и не запустится. Проверка: `node -v`. (Можно положить Node в архив — владелец отказался пока; решается отдельной задачей.)
3. **Google Chrome** в `/Applications/Google Chrome.app`. Проверить, что установленная версия Chrome запускается на этой macOS (для Monterey может потребоваться более старая версия — не проверялось). Путь и флаги Chrome заданы в `cast-app/start.js` (`CHROME`).
4. **Первый запуск.** Если архив пришёл по AirDrop/скачан — карантин macOS: правый клик по `LOST.app` → «Открыть» (или `xattr -dr com.apple.quarantine LOST`).
5. **Монитор.** Waveshare 6.25" по HDMI. «Системные настройки → Мониторы»: **расширенный дисплей** (не зеркало) и **поворот 90°/270°** так, чтобы таймер читался. Имя экрана в macOS должно совпасть с `"display": "Waveshare-625"` в `cast-app/config.json` (иначе берётся последний подключённый экран; если это не он — поправить имя).
6. **Размер таймера.** Сцена `"stage": 1560×720` в `config.json` соответствует панели после поворота (1560×720). Если у нового Мака панель видна в другом разрешении — поправить `stage` и проверить центровку (границы цифр слева/справа/сверху/снизу должны отличаться ≤ 1–2 px).
7. **Звук.** Меню (клик по `>:` в терминале) → «Звук: динамики Мака / монитор (HDMI) / выкл». Проверить, что помощник видит выходы: `cast-app/bin/lost-audio list`. При старте применяется сохранённый режим (`cast-app/.state.json`).
8. **Проверка работы:** таймер `108:00` на панели; в терминале ввод `4 8 15 16 23 42` + Enter в последние 4 минуты сбрасывает таймер (для быстрого теста: Dev Mode → «Таймер: 4 минуты»); пауза; звук вкл/выкл; выход: пункт «Выход» в меню, закрытие окна терминала (~10 с) или ⌘Q у значка LOST в Dock — всё останавливается.

## Дополнение: два процесса Chrome (так задумано)
`LOST.app` запускает **два отдельных экземпляра Chrome** с временными профилями (`lost-timer-profile` — окно таймера, `lost-terminal-profile` — терминал), потому что флаги
(антиторможение фоновых окон, масштаб 1:1, автозвук) применяются к процессу целиком. Обычный Chrome владельца они не затрагивают; при выходе завершаются оба.
Цена — два значка в Dock и ~2× памяти. **На Mac mini 2014 проверить, хватает ли памяти**; если нет — объединять в один процесс (потребует позиционирования окна после старта).

## 2026-10-15 — клавиатура, «Сон», экономный Mac mini
**Клавиши в терминале** (мыши у Mac mini нет; работают и в русской раскладке): `P` пауза, `S` звук (динамики → HDMI → выкл), `D`/`L` Dev/Live Mode, `M` меню, `Q` дважды за 3 с — выход, `Esc` закрыть меню, стрелки — ходить по меню, `Enter` — выбрать пункт. Код по-прежнему цифрами и пробелами + Enter.

**«Фокус: Сон» → пауза.** Mac mini на другом Apple ID, поэтому «Сон» приходит с iPhone через «Команды» по домашней сети (без Tailscale):
- Автоматизация «Когда включается фокус Сон» → действие «Получить содержимое URL» `http://Mac-mini-AK.local:8765/__sleep?on=1`.
- Автоматизация «Когда выключается фокус Сон» → `http://Mac-mini-AK.local:8765/__sleep?on=0`.
- В обеих выключить «Спрашивать перед запуском». Ответ сервера: «LOST: сон, пауза» / «LOST: работает».
- Снимается только пауза, поставленная сном; ручная пауза остаётся. После перезагрузки страницы таймера сон применяется снова.

**Значок LOST.app**: опрос сервера каждые 4 с держал ~15 % CPU — теперь программа сама закрывает значок при выходе, опрос раз в минуту (страховка). Исходник: `cast-app/LOST.applescript` → `osacompile -o LOST.app/Contents/Resources/Scripts/main.scpt cast-app/LOST.applescript`.

**Автозапуск**: `cast-app/com.exrector.lost.plist` (LOST_APP_PATH → путь к LOST.app) в `~/Library/LaunchAgents/`. Для работы без участия человека нужен автовход пользователя (FileVault выключен — возможно): Системные настройки → Пользователи и группы → Автоматический вход.

**Экономия:**
- Без sudo (сделано): службы GoogleUpdater/Keystone сняты (в Корзине `GoogleUpdater-agents-20261015`); папка `~/Library/Application Support/Google/GoogleUpdater` заменена пустым файлом с `chflags uchg` — Chrome не может переставить обновлятор (откат: `chflags nouchg` + удалить файл).
- С sudo: `mac-mini/optimize-sudo.sh` — Spotlight выкл, автообновления macOS/App Store выкл, Power Nap выкл.
- Оставлены: Tailscale, AdGuard VPN, LOST.
- 2026-10-15: «залипающие» клавиши на Mac mini. Физической клавиатуры нет (по Bluetooth — только мышь), ввод идёт через «Экран Mac mini»; при потере события отпускания клавиши macOS повторяет её до следующего нажатия. Автоповтор выключен: `defaults write -g InitialKeyRepeat -int 300000` и `KeyRepeat -int 300000` (действует после повторного входа; откат — `defaults delete -g InitialKeyRepeat` / `KeyRepeat`). Лечилось перезагрузкой. Версия про Teensy (Informer по USB) — ошибочна. Хоткеи проверять программно (`dispatchEvent`), не нажатиями.

- 2026-10-15: проверка клавиш владельцем на Mac mini — P, M, стрелки доходят до терминала (журнал `[console log]`). Клавиатура Informer (Teensy) дребезжит: одна `M` пришла дважды за секунду → меню открывалось и закрывалось обратно. Повтор той же клавиши < 250 мс игнорируется. Меню закрывается `M` или `Esc`.

## 2026-10-15 — «Сон» через общую папку iCloud Drive (работает и вне дома)
- Mac mini вошёл в iCloud как `[Apple ID владельца]`, у iPhone другой Apple ID → общая папка iCloud Drive `LOST` (владелец — iPhone, доступ на изменение — [Apple ID владельца]).

## 2026-10-15 — удалённый пульт LOST (iMessage и локальная сеть)
iMessage с номеров `config.json → sleepFrom` на Apple ID Mac mini = команды; на каждую LOST отвечает сообщением со статусом (при первой отправке macOS спросит разрешение на управление «Сообщениями»). То же по сети: `GET /__cmd?text=…` (ответ текстом).
| Сообщение | Действие |
|---|---|
| Пауза / Сон / Стоп | пауза |
| Старт / Утро / Подъём / Продолжить | старт |
| Звук | следующий выход: динамики → HDMI → выкл |
| Звук выкл / Динамики / Монитор | конкретный выход |
| Статус | только ответ: идёт/пауза, сколько осталось, звук |
| `4 8 15 16 23 42` | код — принимается только в последние 4 минуты (как в терминале; сам таймер код принимает всегда — проверку делает сервер) |
Выход и Dev Mode по сообщению намеренно недоступны. `/__sleep?on=1|0` остаётся.
- 2026-10-15: поправка — на macOS «Фокус: Сон» вручную не создаётся (появляется только синхронизацией с iPhone под тем же Apple ID). У Mac mini другой Apple ID, поэтому «Сна» на нём не будет; ночная пауза LOST идёт через iMessage-пульт («Сон»/«Утро»), «Фокус» Мака не нужен.
- 2026-10-15: **свои команды по слову.** На Monterey в «Командах» нет автоматизаций (они появились в macOS 26), поэтому триггер — LOST: если текст iMessage (или `/__cmd?text=`) **точно** совпадает с названием команды в «Командах» Mac mini (без учёта регистра), LOST запускает её (`shortcuts run`, до 2 мин) и отвечает сообщением с её результатом. Проверка порядка: сначала код из цифр, потом своя команда, потом встроенные слова — так своей командой можно переопределить встроенное слово. Список команд кэшируется на минуту.
- 2026-10-15: **таймер продолжает с того же места** после перезапуска LOST и при переключении Dev/Live. Остаток и пауза — в `cast-app/.state.json` (раз в 10 с и при выходе), сервер подставляет их в страницу (`__LOST_RESUME`), мост ставит `?seconds=` и восстанавливает паузу. Явный `?seconds=` кнопок Dev-панели важнее. Время, пока LOST выключен, не идёт; дошёл до нуля — снова 108.
  - Грабли: исходный таймер при старте рисует секунды, а выше 4 минут их не обновляет — при продолжении было `108:27`. Секундные цифры обнуляются **после того, как таймер нарисован**: jQuery 3 запускает `$(fn)` асинхронно, уже после `load` (первая попытка на `load` не срабатывала). Пауза восстанавливается тоже только после отрисовки (иначе клик по кнопке до появления обработчика теряется).
  - Проверено на Mac mini: перезапуск → `105:00`; пауза пережила перезапуск; Dev → Live — 6098 → 6093 с, `102:00`. Журнал: `[tv log] на панели: …`.

## 2026-10-15 — GitHub с Mac mini: причина и решение
- **Причина — провайдер, не Mac mini.** Прямой путь из дома к GitHub рвётся: с MacBook в обход VPN (`curl --interface en0`) — соединение 3 с и обрыв через 15 с / 21 КБ и зависание. MacBook этого не видит, потому что ходит через AdGuard VPN (`utun5`). Отсюда же ночные ~20 КБ/с с nodejs.org.
- **Решение:** на Mac mini постоянно включён AdGuard VPN (локация Рига, автозапуск). Проверка: `github.com` → `utun3`, 3/3 запроса < 1 с, `git pull` проходит. Локальная сеть (роутер) — напрямую через `en1`, пульт LOST работает.
- Сейчас AdGuard на Mac mini в **общем режиме** (весь интернет через VPN, `apple.com` тоже через `utun3`); iMessage-пульт при этом работает. Если нужен только GitHub — режим «Выборочный» + `github.com`, `githubusercontent.com`, `codeload.github.com`, `nodejs.org`. Kill Switch держать выключенным.
- Попутно: Tailscale на Mac mini в состоянии **Logged out** (`WantRunning=false`) — войти заново через значок Tailscale в строке меню.

Включено: Tailscale SSH (`--ssh`), маршрут в домашнюю сеть `192.168.1.0/24` (объявлен и одобрен через API), `net.inet.ip.forwarding=1` (+ `/etc/sysctl.conf`), operator `exrectormini` (tailscale без sudo), ключ **без срока действия** (API `keyExpiryDisabled`), DNS Tailscale выкл (DNS ведёт AdGuard VPN).

## 2026-10-24 — независимые часы ядра вместо JavaScript-интервала окна

### 2026-10-25 — аудио по кадру и нативный общий аудиотакт

Ядро теперь публикует состояние на следующей целой секундной границе. Нативный хост использует AVAudioEngine: все десять оригинальных MP3 декодированы в PCM заранее, узлы эффектов одного шага запускаются по общему hostTime. Усиление каждого узла и микшера постоянное; системная громкость не изменяется. WKWebView больше параллельно не проигрывает эти эффекты. OFF отменяет ожидающие звуки; смена/закрытие страницы TV, завершение WebContentProcess и приложения останавливают старое аудио. Для видимого отсчёта tick/beep/alarm ожидают реального transitionstart вращаемой половинки; звук перестал опережать рисование. Для скрытой страницы используется фоновый путь. Диагностика читает реальные события и больше сама не проигрывает MP3. Резервный путь HTML использует preload=auto и rewind перед каждым эффектом. Последовательность предупреждений исходная: tick на минутных границах, затем каждую секунду ниже 240; beep по чётным секундам ниже 240 и выше 60; alarm по чётным секундам на последней минуте и каждую секунду ниже 10. Systemfailure начинается через секунду после spinup/discharge.

У половинок цифр backface-visibility:hidden, исходные 0,7 s ease-in и маски сохранены для native; обход Chromecast с clip-path не применяется к WKWebView. Анимации имеют идемпотентное завершение, фильтр transitionend, защиту от повторных снимков, очистку на сбросе и timeout 850 мс.
